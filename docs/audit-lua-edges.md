# Lua edge-behavior audit

This tranche compares callable non-BattleTech Lua behavior with the C server, beyond symbol presence. It covers omitted and `nil` arguments, coercion and error identity, malformed callback results, stale identities, nested protected calls, flows, schedules, reload, and checking mode. Comsys was excluded because it was audited separately.

## Baseline and method

The C reference is the source under `btmux-khi/src/mux/lua`; the Rust candidate is the current working tree. All execution used temporary copies of `tests/fixtures/game`. No production game directory, database, process, or network listener was changed. Direct execution was used where the Rust fixture can exercise a public callable. Source evidence is identified separately; the corrected cases are explicit binding/access branches that do not require server I/O.

The audit preserves the accepted Rust contracts: transaction-wide rollback and staged effects, original movement causes and descriptor safety, configured instruction/memory/state/output limits, session-owned `CONNECTED`, Markdown and Unicode support, captured schedule registration, removed command forms, and no BattleTech API.

| LE06 | Malformed lock/message/appearance results | C accepts lock booleans or a table with only `passes`, `enactor_message`, and `other_message`; message providers accept only their allowed string fields; appearance requires a string (`lua_callbacks.c:469-615`, appearance callback branches earlier in that file). | LE08 | Nested `pcall` and error values | Native argument errors remain ordinary Lua errors; typed host failures become structured values; arbitrary Lua error values retain identity. Failed nested native callback work cannot leak staged world/output/flow/log effects. | Rust preserves intervening nil returns, arbitrary error identity, bounded traceback attachment, and nested rollback. | Existing execution in `tests/lua_parity.rs`, `tests/logging.rs`, `tests/locks.rs`, and movement parity tests; aligned with the approved transactional model. |
| LE09 | Interactive flow outcomes and scratch | C reloads the named module/step, defaults a missing action to repeat, preserves C-owned scratch across VM replacement, and cancels malformed outcomes. It rejects malformed/oversized scratch and outcomes and rolls their effects back, instead of truncating or retaining callback effects. | Existing TCP execution in `tests/foundation.rs`. | LE10 | Schedule capture, stale targets, clock movement, reload, and failures | C registers path/name/cron, then finds the named handler in the active module when the job runs; it skips missing/GOING objects and consumes failed attempts (`lua_schedule.c:140-215`). | Rust intentionally captures the validated handler and metadata, captures object incarnation, skips stale/GOING targets, consumes failures, does not backfill missed minutes, and discards queued jobs on successful reload while retaining the minute high-water mark. | Executed coverage in `tests/schedules.rs`; retained the approved captured-registration contract. |
| LE11 | Checking VM | C marks a fresh isolated VM as checking; live world/session/telnet/state/repair/log services reject use while pure config/text/error facilities remain callable (`lua_validation.c:146-199` and package runtime guards). | Rust installs built-ins before source validation and replaces live native entry points with typed `mux.unavailable.checking` failures. ## Corrections

Five discrepancies were corrected. Optional tables and optional identities now distinguish `false` from omitted/`nil`, matching C without weakening type checks. Batched state values now pass through the same per-value limit conversion as single writes, so the stable error code is `mux.state.value_too_large` and no member of an invalid batch is published. Object identities now use finite, in-range Lua numeric coercion before the existing object and incarnation checks. `contents` now applies the public API's C visibility and receiver rules without widening generic administrative visibility.

Focused regressions are `public_catalog_and_structured_errors` in `tests/lua_parity.rs` and `typed_objects_relationships_and_enumeration` in `tests/lua_admin.rs`. They cover both accepted absence forms, the rejected `false` forms, the exact oversized-state code and atomicity, numeric identity conversion including NaN/infinity, and contents visibility/container combinations.

## Limits

No new paired C/Rust TCP transcript was captured. Callback, flow, schedule, reload, and checking conclusions combine direct source tracing with existing Rust integration/TCP regressions; they should not be read as exhaustive differential execution of every malformed Lua value. In particular, this tranche does not claim byte-for-byte log-message parity, scheduling behavior across wall-clock/DST changes beyond the UTC cron tests, or parity for BattleTech and comsys APIs.
